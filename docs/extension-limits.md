# Gate Inbox v1.1.0 extension API notes

Gate Inbox Machines builds against stock v1.1.0. These notes describe what the prototype uses and where native multi-machine support could take over.

## How the extension plugs in

| Prototype | Gate Inbox v1.1.0 contract |
| --- | --- |

The picker probes tools on the worker and runs stock `spawn` over SSH for agents. | [`CLIProvider`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/cli.go), [`Host` and `SessionService`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/host.go) |

## Where the model falls short

### Session identity and lifecycle

**Today.** A mirror is a local helper row with a local ID, working directory, group, priority, and lifecycle. The extension stores the worker and remote ID in `mirrors.json`. Worker group membership and parent IDs travel in the reply. The launch files each mirror as a standalone row in an existing local group. The API offers read access and helper launches, with no operation to create groups or update a mirror's metadata when the original row is renamed. The remote directory is a detail line because the local launch directory still has to exist on the controller. Dismissal archives the local SSH pane, leaving the worker's agent running. Stock revive and restore rebuild the command without the original launch arguments. `runAttach` uses the local row ID to recover the target. See [`launchRequest`, `decorate`, and `readState`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/board.go), [`runAttach`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/machines.go), [`SessionInfo`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/host.go), and [`relaunchSession`](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/ui/lifecycle.go).

**Native option.** Add a session source with a stable worker-board identity and a source-scoped row ID. Define which fields belong to the worker and which are local overrides. Give remote rows explicit local hide and remote stop actions. This lets the board render remote metadata without launching a stand-in pane for every row. It also makes identity, cache migration, and permissions part of core. A smaller extension API change would preserve role-specific launch arguments, but would leave the duplicate row model in place.

### Conversation preview and input

**Today.** The terminal attaches over SSH. The stock conversation view looks for local history by tool, directory, and conversation ID, so a mirror has none. The stock preview does read the mirror pane's screen, and when a dialog is visible it draws a question card from the parsed text ([`previewScreen`](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/ui/previewquestions.go)). That card comes from screen text, not from the worker's saved question, so wrapped options can repeat and a dialog scrolled out of view disappears. Within a worker, the public API can read a pane, a transcript, and a dialog, but it has no callback for supplying the selected row's conversation preview or question card. Commit [`6252d31`](https://github.com/hung-ng/gate-inbox-machines/commit/6252d31) added those callbacks and a worker preview command in a patch. [`e826814`](https://github.com/hung-ng/gate-inbox-machines/commit/e826814) removed both to return to stock.

The mirror tool declares no input cutoff so stock queued sends refuse it. It also skips the automatic rename directive. Those choices do not cover every input path. Stock snippets call `sendSentence` and `r` calls `smartRenameSelected`. Neither path consults a mirror-specific guard, so a remote dialog can receive keystrokes while it is out of view. Read and answer in the worker's terminal. See [`ConfigDefaults`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/machines.go), [`Board.ReadPane`, `Transcript`, and `Answer`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/board.go), [the stock conversation reader](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/ui/conversation.go), [snippet sends](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/ui/snippets.go), [direct sends](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/ui/send.go), [smart rename](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/ui/smartrename.go), and [queued-send checks](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/sessioncmd/session.go).

**Native option.** Let a session source return bounded preview data for the active row and declare which actions it supports. Route structured replies through the worker, where the current prompt and its answer rules are known. A preview callback is a smaller change that improves reading on its own. Sending requires prompt identity checks, a stale-answer policy, and a receipt for delivery. Disable unsupported writes before touching the pane.

### Terminal targets, scroll mode, and remote shells

**Today.** The worker intersects board rows with tmux sessions named `gi_<id>`. An adopted pane can live in a window with unrelated panes. Core keeps its socket and pane ID, but `SessionInfo` does not expose those targets and SSH attaches to a tmux session, which would expose the containing session. The prototype skips these panes. The remote tmux client can receive scroll input. The extension polls pane mode and shows a hint when the worker is in scroll mode. The public launch methods launch agents. The prototype's **Terminal** option creates and marks its own detached tmux session so it can be discovered without creating a fake worker agent row. Shell tabs nested under agents are excluded from the worker snapshot. See [`listSessions`, `tmuxSessions`, and `tmuxScrolling`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/wire.go), [`attachArgv`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/ssh.go), [`runTerminal`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/terminal.go), [the core store's adopted targets](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/store/store.go), and [`ToolInfo.Shell`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/tools.go).

**Native option.** Have the worker open a pane-scoped terminal and control resize and input routing. Let the session source launch and enumerate shells through the worker board. This could include adopted panes and child shells, but needs to preserve their ownership and avoid manipulating other windows. A terminal transport needs PTY negotiation, backpressure, and a policy for simultaneous clients. Keep raw tmux coordinates on the worker so the controller can address panes by session identity.

### Status and availability

**Today.** `Subscribe` and `OnPass` observe the board in the same process. The controller polls full replies over SSH, in parallel across workers, and waits for the last reply or timeout before reconciling. `PinStatus` accepts five values, so starting maps to working and delegating or background maps to finished. When the worker cannot report fresh status, the extension keeps the last pin and uses `UIHost.Own` to exclude the row from triage. The flag's API describes question ownership. There is no separate availability flag on a row.

The worker command reads the PID from `manager.lock` and checks that a process with the PID exists. It avoids taking the lock, which could interfere with the board's singleton takeover. This is a liveness hint and can be fooled by PID reuse. Listing also depends on an up-to-date worker board and on two views of state, the board list and tmux. Unparented list pages use the current board ordering, so concurrent moves can skip or repeat rows. The extension rejects detected incomplete scans and checks saved local IDs missing from the list. The missing-row check relies on stock error text because there is no typed not-found error. See [`loop`, `observe`, and `localRows`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/board.go), [`pinStatus`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/plan.go), [`allSessions` and `boardRunning`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/wire.go), [`BoardHost`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/lifecycle.go), [`SessionFilter.After`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/host.go), [core session lookup](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/sessioncmd/session.go), and [the singleton lock](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/singleton/singleton.go).

**Native option.** Publish a versioned snapshot and an ordered status stream for each worker board. Resume from a cursor or fetch a new snapshot after a gap. Give freshness and reachability their own fields so the queue can distinguish a stale waiting session from a live one. A stream reduces repeated scans and the time before a new question appears. It adds connection state and resync rules. Stable snapshots and typed lookup errors would improve the polling design even without a stream.

### Worker configuration and resource readings

**Today.** `Host` gives the extension its config directory and configured tool names, with no resolved tmux target or tool installation check. The helper reads `tmux_socket` from the worker's config and checks overridden commands against the worker's login-shell PATH. An environment-only socket must also be visible to the worker command on first discovery. The controller can put worker CPU and RAM in a row fact. The board's computer meters and local process usage are read from the controller. See [`boardSocket`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/about.go), [`installedTools`](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/tools.go), [worker readings](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/worker_stats.go), [`Host`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/host.go), [`ToolInfo`](https://github.com/usestring/gate-inbox/blob/v1.1.0/extension/tools.go), and [stock sidebar rendering](https://github.com/usestring/gate-inbox/blob/v1.1.0/internal/ui/listview.go).

**Native option.** Let the worker report its resolved session backend and launch capabilities. Report host and session metrics as distinct data so the UI can label each reading and show its age. Narrow capability methods avoid exposing the entire config or publishing local executable paths. Metrics add a sampling and retention cost, so they can be optional.

### macOS login keychain

**Today.** `N` invokes the worker's launch command through its login shell. The agent runs in a tmux server, whose desktop login context can matter to tools using the login keychain. A tmux server started over SSH can lack that context. Starting the worker's tmux server from its desktop session is the documented setup for this case. The operating system sets this context when the tmux server starts. See [the remote launch command](https://github.com/hung-ng/gate-inbox-machines/blob/d6416a6/machines/spawn.go) and [the original reproduction and setup note](https://github.com/hung-ng/gate-inbox-machines/commit/f58cff6).

**Native option.** Route launches through an already running worker with the right desktop context, or report that the selected worker lacks it. This would remove the need for the SSH call to create the tmux server. It requires a desktop-session worker lifecycle and cannot give an absent login session access to a user's keychain.
